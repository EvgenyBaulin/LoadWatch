# Сценарии

**Сценарий = профиль нагрузки + поток запросов + SLO.** Поток описывает, что делает один виртуальный пользователь; профиль — сколько таких проходов запускать в секунду.

```json
{
  "name": "Логин и личный кабинет",
  "load_profile": {"type": "constant", "rate": 10, "duration_sec": 60},
  "flow": [ … шаги … ],
  "apdex_t_ms": 500,
  "slo_p95_ms": 800,
  "slo_max_error_rate": 0.01
}
```

`POST /api/v1/sites/{id}/scenarios` — создать, `PUT /api/v1/scenarios/{id}` — заменить целиком (секреты при этом сохраняются).

## Профили нагрузки

| Тип | Параметры | Что делает |
| --- | --- | --- |
| `constant` | `rate`, `duration_sec` | Постоянно `rate` проходов в секунду |
| `ramp_up` | `start_rate`, `end_rate`, `ramp_sec`, `hold_sec` | Плавный рост, затем удержание (рост не может убывать) |
| `step` | `start_rate`, `step_rate`, `step_duration_sec` (≥ 5), `max_steps`, `max_error_rate` (0.05), `max_p95_ms` | Ступени, пока сайт держит пороги; итог — потолок `ceiling_rps` |

Нагрузка «как живые посетители»: проходы стартуют по расписанию, даже если прошлые ещё не закончились. Если все `MAX_CONCURRENCY` слотов заняты, проход «сброшен» (`iterations.dropped`), и это видно в отчёте. Параметры выше лимитов сервера обрезаются; итог — в `effective_load_profile`.

## Шаг потока

| Поле | По умолчанию | Описание |
| --- | --- | --- |
| `name` | — | Уникальное имя шага (метрики считаются по шагам) |
| `method` | `GET` | `GET POST PUT PATCH DELETE HEAD` |
| `path` | — | Относительный путь от сайта: `/login`, `/api/items?page=2` |
| `headers` | `{}` | До 20 заголовков; запрещены `Host`, `Content-Length`, `Transfer-Encoding`, `Connection` и hop-by-hop |
| `body` | нет | `{"type": "json"\|"form"\|"raw", "content": …, "content_type"?}`, до 64 КБ, не для GET/HEAD |
| `expected_status` | `["2xx", "3xx"]` | Конкретные коды или классы: `["200", "201"]`, `["4xx"]` |
| `assert_contains` | нет | Подстрока, которая должна быть в первых 64 КБ ответа |
| `extract` | `[]` | Правила извлечения значений в переменные (см. ниже) |
| `think_ms` | `0` | Пауза после шага (до 60 с; в dry-run пропускается) |

Шагов — до 10. Шаг падает при неожиданном статусе, сетевой ошибке, провале assert или extract, и тогда проход прерывается и считается ошибочным. Ошибка видна в «топе ошибок» как `http_503`, `connect_timeout`, `assert_failed`, `extract_failed`, `missing_secret` и т. п.

## Переменные

`{{name}}` подставляются в путь, заголовки, тело и `assert_contains`.

| Переменная | Значение |
| --- | --- |
| `{{token}}` (любое имя) | Извлечена на одном из **предыдущих** шагов — это проверяется при сохранении |
| `{{uuid}}` | Случайный UUID на каждую подстановку |
| `{{rand_int}}` | Случайное целое 0…1 000 000 |
| `{{timestamp}}` | Unix-время в секундах |
| `{{secret.NAME}}` | Секрет сценария (см. ниже) |

В **пути** значение кодируется целиком: `/search/{{q}}` при `q = "a b/c"` → `/search/a%20b%2Fc`. В заголовках и теле подставляется как есть; перевод строки или не-ASCII в итоговом заголовке — ошибка `invalid_header`.

## Извлечение (`extract`)

```json
{"var": "token", "source": "json", "expr": "data.token"}
```

| `source` | `expr` | Пример |
| --- | --- | --- |
| `json` | Путь в JSON-ответе | `data.items[0].id`, `$.user.name` |
| `header` | Имя заголовка ответа | `X-Request-Id` |
| `cookie` | Имя cookie из `Set-Cookie` | `session` |
| `regex` | Регулярное выражение; берётся первая группа или всё совпадение | `csrf_token" value="([^"]+)"` |

Регулярное выражение ищет по первым 16 КБ ответа с таймаутом 50 мс. Извлечённое значение — не длиннее 4 КБ.

## Cookie

У каждого виртуального пользователя свой набор cookie. Cookie из ответов (`Set-Cookie`) автоматически отправляются в следующих шагах с учётом `Path`, `Secure`, `Max-Age`/`Expires`; cookie чужого домена не принимаются. Свой заголовок `Cookie` в шаге объединяется с ними.

## Секреты

Пароли и токены тестового аккаунта не пишут в сценарий открытым текстом:

```http
PUT /api/v1/scenarios/{id}/secrets
{"secrets": {"PASSWORD": "s3cret", "OLD_ONE": null}}
```

Строка задаёт значение, `null` удаляет. Значение шифруется (Fernet) и больше не показывается: в ответах — `"********"`. В шагах используйте `{{secret.PASSWORD}}`. Поле `missing_secrets` в ответе сценария показывает, какие секреты поток использует, но они не заданы. С незаданным секретом тест не запустится (`missing_secrets`).

## Пример: главная → логин → защищённая страница

```json
{
  "name": "Логин",
  "load_profile": {"type": "constant", "rate": 5, "duration_sec": 60},
  "slo_p95_ms": 500,
  "slo_max_error_rate": 0.01,
  "flow": [
    {"name": "главная", "path": "/"},
    {
      "name": "логин",
      "method": "POST",
      "path": "/api/login",
      "body": {"type": "json", "content": {"username": "demo", "password": "{{secret.PASSWORD}}"}},
      "extract": [{"var": "token", "source": "json", "expr": "data.token"}]
    },
    {
      "name": "кабинет",
      "path": "/dashboard",
      "headers": {"Authorization": "Bearer {{token}}"},
      "assert_contains": "Welcome",
      "think_ms": 1000
    }
  ]
}
```

После сохранения задайте секрет `PASSWORD` и нажмите **Dry-run** (`POST /api/v1/scenarios/{id}/dry-run`). Это один проход одним пользователем: по каждому шагу будут статус, тайминги, извлечённые переменные (секреты замаскированы) и причина падения. Dry-run работает только для подтверждённого сайта, не дольше 60 секунд и не больше 5 раз в минуту.

## Ступенчатый тест: где потолок сайта

```json
{
  "name": "Потолок",
  "load_profile": {"type": "step", "start_rate": 10, "step_rate": 10,
                   "step_duration_sec": 30, "max_steps": 10,
                   "max_error_rate": 0.05, "max_p95_ms": 1000},
  "flow": [{"name": "главная", "path": "/"}]
}
```

Нагрузка растёт ступенями по 30 секунд. Первая ступень, где ошибок больше 5% или p95 выше 1 с, останавливает тест. Потолок (`ceiling_rps`) — реальный RPS последней прошедшей ступени. Если не справляется сам генератор, потолок не выдаётся, чтобы не принять насыщение генератора за предел сайта.
